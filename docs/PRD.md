# leader-console 产品需求（v0.3）

> 基于 leader 整理的 v0.2（用户已确认方向）补全。新增内容：§6 MVP 范围、§7 页面原型、§8 状态与列映射、§10 验收细化、§11 待决策点。
> 技术方案见 [design.md](design.md)，leader 协议改造见 [leader-protocol.md](leader-protocol.md)，并行任务见 [tasks.md](tasks.md)。

## 1. 背景与痛点

用户以“leader 模式”工作：一个 leader（Claude Code，`claude --agent leader`）在 herdr 里调度多个 worker（Claude/Codex），负责拆任务、派发、验收、汇报。痛点：所有任务、结果和待确认事项都挤在一个 leader 对话框里，用户需要频繁翻上下文查看某个任务的结果和需要自己确认的信息。

以现有项目 `tob-check-estimated-balance` 为例：一天内台账累积 40 余个任务、十几条“等用户确认提交 / 待用户决定”的结论散落在“结果”列和备注里，没有统一入口，也没有回答渠道。

## 2. 已确认的方向

- 形态：本地 Web 页面。本机常驻一个轻量服务，只监听 127.0.0.1，用浏览器访问，数据不出本机。
- MVP 就支持在面板上做决策，并回传给 leader。
- 覆盖本机所有 leader 项目，即汇总 `~/.leader/*/`。

## 3. 目标 / 非目标

**目标**：打开页面 30 秒内能回答三个问题——
1. 现在要我决定什么？
2. 各任务进展如何？
3. 某个任务的最终结果是什么？

并且可以在面板上直接做决策。

**非目标**：
- 不替代 leader 的调度（派发、验收、返工仍由 leader 负责）。
- 不做通用项目管理工具（不建任务、不拖拽改状态、不分配人）。
- 不在面板里编辑代码。
- 面板不能派发任务，也不能执行任意命令；唯一的写动作是“回传决策”。
- 不做多用户 / 远程访问 / 登录体系。

## 4. 现状（leader 目前的数据）

- 台账：`~/.leader/<项目目录名>/ledger.md`，Markdown 表，列为 `name | kind | pane | worktree | 目标 | 状态 | 结果 | 更新时间 | 已通知`，表后有“## 备注”“## 复盘”等段落。状态取值：working / blocked / needs_user / reviewing / done / failed / lost。
- worker 报告写在 `/tmp/<name>.md`，重启后会丢。
- 实时状态来自 herdr CLI（实测 herdr 0.9.3）：
  - `herdr agent list` 返回 `{"id":"cli:agent:list","result":{"agents":[...]}}`，每个 agent 有 `agent`(claude/codex)、`agent_status`(idle/working/blocked/done/unknown)、`pane_id`、`tab_id`、`workspace_id`、`cwd`、`terminal_title(_stripped)`；**`name` 只有被命名的 agent 才有**（当前 leader 本身就没有名字），Claude 有 `agent_session.value`（会话 id），Codex 没有。
  - `herdr agent get <target>`：target 可以是名字或 pane_id；找不到时退出码 1，输出 `{"error":{"code":"agent_not_found",...}}`。
  - `herdr agent read <target> --source visible|recent --lines N` 输出终端纯文本。
  - `herdr agent prompt <target> "<text>"`：若 agent 处于 blocked 会被拒（`agent_blocked`）。
- 定期汇报：leader 每 10 分钟由 cron 触发一次【定期汇报】。

## 5. 数据契约（leader 协议改造核心）

每个项目目录 `~/.leader/<project>/` 下：

| 文件 | 写入方 | 写法 | 内容 |
|---|---|---|---|
| `leader.json` | leader | 整文件原子替换 | 项目名、cwd、leader 在 herdr 中的名字 / pane / 会话 id、最后心跳 |
| `state.json` | leader | 整文件原子替换 | 结构化台账：任务列表（id、name、kind、pane、仓库/分支/worktree、目标、状态、结果摘要、报告、外部链接、返工次数、时间） |
| `events.jsonl` | leader | 只追加 | 事件流：派发、开工、阻塞、评审、返工、合入、通知、决策确认 |
| `decisions.jsonl` | leader | 只追加（同 id 后写覆盖） | 待用户决定的事项：问题、背景、选项（说明+影响）、推荐项、截止时间、状态（open/answered/expired/superseded） |
| `answers.jsonl` | **面板** | 只追加 | 用户回答与投递状态 |
| `reports/<task>/*.md` | worker | 普通文件 | 报告、评审、返工记录（替代 /tmp） |
| `ledger.md` | leader | 由 state.json 生成 | 保留给人直接看 |

字段定义、示例见 design.md §4。过渡期（leader 协议未改前）面板只读解析 `ledger.md`，见 design.md §5。

## 7. 页面原型

全局布局：毛玻璃侧栏导航（窄屏为顶栏），三个页面：`/`（待我决定）、`/board/?project=`、`/task/?project=&id=`（旧的 hash 链接 `#/decisions`、`#/board`、`#/task/<project>/<id>` 自动跳转）。

交互：
- 选项单选；`allow_free_text` 时可只填文本或选项 + 补充说明；提交按钮二次确认（“提交后不可修改”）。
- 提交后卡片立即变为“已记录”，状态随 SSE 推进；同一决策只允许一次回答（服务端 409 兜底）。
- 投递失败（自动重试用尽）显示“重试投递”，只重发同一条回答，不能改答案。

## 8. 状态与看板列映射

| 任务状态 | 看板列 | 说明 |
|---|---|---|
| queued / working | 进行中 | queued 为协议新增：已建任务未派发 |
| blocked / needs_user | 阻塞/异常 | needs_user 同时应对应一条 open 决策 |
| failed / lost | 阻塞/异常 | 红色徽标；对账发现 lost 的进行中任务也会显示在这里（只展示，不回写） |
| reviewing | 评审中 | |
| ready_to_merge | 待合入 | 协议新增：验收/评审通过、等用户授权提交或等合入 |
| done | 已完成 | |

过渡期（ledger.md）：没有 ready_to_merge，状态为 done 且结果匹配“等(待)用户(确认|授权).*(提交|合入|MR)”“交.*合入”的任务归入“待合入”。

## 9. 通知

只有新增决策和失败才推送；对话框里只保留一行“新增 N 条待决策，见面板 http://127.0.0.1:7788/”。（leader 侧规则，见 leader-protocol.md）

## 10. 安全

- 只监听回环地址（非回环地址启动即失败）；校验 `Host` 头，防 DNS rebinding。
- 写接口必须带启动时生成的随机 token（`X-LC-Token`），并校验 `Origin`；token 由服务端注入首页，不落盘。
- 报告、终端输出、结果摘要、决策背景在展示前对疑似凭证（AK/SK、token、私钥、JWT、`password=` 等）脱敏。
- 面板不能派发任务，也不能执行任意命令；唯一的外部命令是固定参数的 `herdr agent list/get/read/prompt`（只有 prompt 是写，且文本由服务端按固定模板生成）。

## 11. MVP 验收

1. 3 个以上项目同时运行时，打开面板 10 秒内看到全部待决策和任务状态（目标：首屏 < 2s）。
2. 从点击选项到 leader 收到并在事件流里写入 `decision_ack`，不超过 30 秒（面板侧：追加 + 投递 < 3s；扫描间隔 2s；其余为 leader 处理时间）。
3. 重启 herdr 或 leader 后，面板数据不丢（全在文件里），能和 herdr 当前状态对账，并标出 lost 的 worker。
4. 过渡期：对现有 `~/.leader/tob-check-estimated-balance/ledger.md` 能正确解析出全部任务行，不把备注/复盘段落当任务。
5. 安全：非回环地址拒绝启动；无 token / 错 Origin / 错 Host 的写请求返回 403；报告中的示例凭证被打码。
